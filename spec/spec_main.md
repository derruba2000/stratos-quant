## 2. Database Layer Extensions

To support the allocation engines, target matrices, and LLM rationale audits, you need to append the following relational tables to your existing SQLite schema. These bridge your live structural data (`portfolios`, `transactions`, `securities`) with your quantitative execution layers.

```sql
-- Extension Table 1: strategy_runs
-- Tracks every execution of the quantitative engine and the subsequent LLM advisory audit.
CREATE TABLE strategy_runs (
    id INTEGER NOT NULL,
    run_timestamp DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    allocation_model VARCHAR(32) NOT NULL, -- 'HIERARCHICAL' or 'ENSEMBLE'
    llm_model_used VARCHAR(64) NOT NULL,
    llm_overall_rationale TEXT,
    PRIMARY KEY (id)
);

-- Extension Table 2: strategy_target_allocations
-- Stores the deterministic "Target Vector" generated by the math models (Hierarchical/Ensemble).
CREATE TABLE strategy_target_allocations (
    id INTEGER NOT NULL,
    run_id INTEGER NOT NULL,
    portfolio_id INTEGER NOT NULL,
    asset_class_code VARCHAR(32) NOT NULL,
    target_weight DECIMAL(32, 10) NOT NULL, -- e.g., 0.6000000000
    PRIMARY KEY (id),
    FOREIGN KEY(run_id) REFERENCES strategy_runs (id),
    FOREIGN KEY(portfolio_id) REFERENCES portfolios (id),
    FOREIGN KEY(asset_class_code) REFERENCES asset_classes (code)
);

-- Extension Table 3: asset_recommendations
-- Connects the asset class weight down to specific candidate tickers, verified and selected by Ollama via KPIs.
CREATE TABLE asset_recommendations (
    id INTEGER NOT NULL,
    run_id INTEGER NOT NULL,
    portfolio_id INTEGER NOT NULL,
    security_id INTEGER NOT NULL,
    action_type VARCHAR(10) NOT NULL, -- 'BUY', 'SELL', 'HOLD'
    target_weight DECIMAL(32, 10) NOT NULL,
    estimated_trade_value DECIMAL(32, 10) NOT NULL, -- Local portfolio currency
    llm_security_rationale TEXT NOT NULL, -- Why Ollama selected this ticker over alternatives using KPIs
    is_executed BOOLEAN NOT NULL DEFAULT 0,
    PRIMARY KEY (id),
    FOREIGN KEY(run_id) REFERENCES strategy_runs (id),
    FOREIGN KEY(portfolio_id) REFERENCES portfolios (id),
    FOREIGN KEY(security_id) REFERENCES securities (id)
);

```

## 3. Product Backlog for AI Agent Implementation

This backlog is structured for programmatic interpretation by an AI software agent (e.g., Devin, Claude Engineer, AutoGPT). It enforces the use of **Python 3.12**, **Poetry**, and strict environmental variable isolation.

### Epic 1: Environment Initialization & Core Infrastructure

> **Objective:** Establish a highly structured Python 3.12 virtual environment using Poetry, configuring secure environment isolation for database pipelines and local Ollama inference networks.

#### User Story 1.1: Poetry Workspace Setup

* **As an** AI Developer Agent,
* **I want to** initialize a Python 3.12 workspace using Poetry,
* **So that** core quantitative and runtime dependencies are structurally locked without version conflicts.
* **Acceptance Criteria:**
* `pyproject.toml` explicitly targets `python = "^3.12"`.
* Dependencies include `pybroker`, `gradio`, `pandas`, `numpy`, `sqlalchemy`, and `requests`.
* Development scope separates testing suites (`pytest`) from runtime environments.



#### User Story 1.2: Environment Configurations (.env Isolation)

* **As an** AI Developer Agent,
* **I want to** build a central environment parsing module using `python-dotenv`,
* **So that** database target destinations and Ollama local endpoint strings are never hardcoded.
* **Acceptance Criteria:**
* System reads `SQLITE_DB_PATH` to discover and connect to the SQLite target file.
* System reads `OLLAMA_MODEL` (e.g., `llama3`, `mistral`, `phi3`) to dictate downstream generative payload strings.
* System validates missing `.env` fields on initialization and throws hard, clean exceptions.

### Epic 3: Quantitative Optimization & Sizing Engines

> **Objective:** Construct two independent mathematical allocators in PyBroker to analyze input pricing series and export definitive asset weight matrices.

#### User Story 3.1: Hierarchical Engine Development

* **As an** AI Developer Agent,
* **I want to** implement the Hierarchical Allocation Engine (Decision Tree Strategy),
* **So that** macro-regimes and dual momentum filters pass hard binary flags before sizing risk.
* **Acceptance Criteria:**
* Checks if security trends are positive via a 50/200 day moving average rule over `price_history`.
* If positive, computes 12-month relative momentum profiles to pick a single winning asset class.
* Applies a volatility adjustment calculation to output a final 100% total weight matrix.



#### User Story 3.2: Ensemble Portfolio Engine Development

* **As an** AI Developer Agent,
* **I want to** implement the Ensemble Allocation Engine (Sub-Portfolio Blending),
* **So that** diverse models contribute fractional weight votes to smooth out rebalancing frequency impacts.
* **Acceptance Criteria:**
* Slices allocation decisions into independent parallel processes (Moving Average Cross, Dual Momentum, Volatility Scaler).
* Aggregates individual strategies linearly (e.g., equal 33.3% structural weights).
* Normalizes final target matrix outputs to sum to exactly 1.0000000000.
